# Proxmox vProxy (emc-vProxy-SPP) — Prerequisites Guide

Cleaned-up, de-duplicated version of the trial-and-error bash history, reordered into a working sequence. Run everything as the `admin` user with `sudo` — do **not** switch to a root shell (`sudo su`).

## 0. Minimum VM requirements for the proxy

This mirrors the external VM Direct Engine sizing used for VM/NAS protection engines.

| Resource | Minimum requirement |
|---|---|
| CPU | 4 vCPU @ 2 GHz (4 virtual sockets, 1 core per socket) |
| Memory | 8 GB RAM |
| Disk 1 | 59 GB |
| Disk 2 | 98 GB |
| Network | One vmxnet3 NIC with one port |
| SCSI controller | 4 (maximum) |
| Internet Protocol | IPv4 only or IPv6 only — Linux package-based components support IPv4 only |

Notes:
* These are minimums — the installer fails to deploy on a host below these values, but will run fine on a host with more resources.
* Up to 25 external VM Direct Engines are supported per vCenter server; 7 is the recommended number.
* For Linux install-package deployments specifically (as used here), every component the proxy communicates with must use IPv4 only, regardless of any IPv6 support elsewhere in the environment.
* Dedicate the host to the protection engine only — do not run other applications or nonsystem services on it.


```bash
#!/bin/bash

VMID=200
VMNAME="proxproxy1"
STORAGE="nfs"
ISO_STORAGE="nfs"
ISO_FILE="Rocky-9.8-x86_64-minimal.iso"
MEMORY=8096
CORES=4

OS_DISK_SIZE=60
DATA_DISK_SIZE=100

BRIDGE="ovsbr0"

qm create ${VMID} \
  --name "${VMNAME}" \
  --ostype l26 \
  --machine q35 \
  --bios seabios \
  --memory ${MEMORY} \
  --cores ${CORES} \
  --sockets 1 \
  --cpu host \
  --scsihw virtio-scsi-single \
  --net0 virtio,bridge=${BRIDGE},firewall=1 \
  --boot order=scsi0\;ide2\;net0 \
  --onboot 1

# OS Disk
qm set ${VMID} \
  --scsi0 ${STORAGE}:${OS_DISK_SIZE},iothread=1

# Installation ISO
qm set ${VMID} \
  --ide2 ${ISO_STORAGE}:iso/${ISO_FILE},media=cdrom

qm start ${VMID}
```

## 6. Run the installer

Run as `admin` with `sudo` (do **not** use `sudo su` — the installer needs root privileges for a single command, not an interactive root shell; running as plain `admin` without `sudo` causes the `mkdir /usr/local/vproxy: Keine Berechtigung` permission error seen earlier).

**Interactive mode:**
```bash
sudo ./installSPP.sh --path=/home/admin/emc-vProxy-SPP/pkg/
```

**Non-interactive mode** (password `Password123!`, protection type Proxmox):
```bash
echo 'Password123!' > /home/admin/.ppdm_pass && chmod 600 /home/admin/.ppdm_pass

# Auto-detect the host's local (management) IP address
PROXY_MGMT_IP=$(hostname -I | awk '{print $1}')
echo "Detected proxy management IP: ${PROXY_MGMT_IP}"

sudo ./installSPP.sh \
  --path=/home/admin/emc-vProxy-SPP/pkg/ \
  --supported-protection-types=Proxmox \
  --proxy-mgmt-ip=${PROXY_MGMT_IP} \
  --proxy-password=Password123! \
  --ppdm-password-file=/home/admin/.ppdm_pass \
  --is-multivlan-enabled=no \
  --proxmox-inventory-source-id=proxmox1.demo.local
```

Note: `hostname -I` returns all IPs bound to the host, space-separated; `awk '{print $1}'` takes the first one. If the host has multiple NICs, verify `${PROXY_MGMT_IP}` resolves to the correct management interface before running the install — on a multi-homed host, use a more specific method instead, e.g. `ip -4 addr show <interface> | grep -oP '(?<=inet\s)\d+(\.\d+){3}'`.

## 7. Harden SSH configuration

```bash
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak.$(date +%Y%m%d%H%M%S)

for setting in "PermitRootLogin no" "ChallengeResponseAuthentication no" "AllowAgentForwarding no"; do
  key=$(awk '{print $1}' <<< "$setting")
  if sudo grep -qiE "^[[:space:]]*#?[[:space:]]*${key}\b" /etc/ssh/sshd_config; then
    sudo sed -i -E "s|^[[:space:]]*#?[[:space:]]*${key}\b.*|${setting}|I" /etc/ssh/sshd_config
  else
    echo "$setting" | sudo tee -a /etc/ssh/sshd_config
  fi
done

sudo sshd -t && sudo systemctl restart sshd

# Verify
sudo grep -iE "PermitRootLogin|ChallengeResponseAuthentication|AllowAgentForwarding" /etc/ssh/sshd_config
```
